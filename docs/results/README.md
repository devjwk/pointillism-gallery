# 실행 결과와 측정의 경계

이 기록은 연구 벤치마크가 아니라, 공개 갤러리와 분리한 검증 도구의 기술적 동작 확인이다.

- [실사진 가시면 파일럿 집계](visible-surface-pilot.json): 2026-10-21에 보관한 실사진 1장·시드 42의 기록을 공개 가능한 필드만 골라 정리했다.
- [코드 실행 검증](verification-summary.json): README 정리 시 로컬에서 다시 실행한 JavaScript·Python CLI 테스트 결과. 사진 품질 평가와 별개의 검사다.

## 입력과 공개 범위

원본은 개인 제공 사진 1장이다. 입력 파일명·입력 SHA-256·사진 픽셀·메쉬 파일·화면 캡처는 공개하지 않는다. 집계에는 모델명, 기하 개수, 총 점 수, 배치 방식, 이미지 차이 수치, 점 버퍼 유지 여부와 검증 범위만 남겼다. 비공개 연구 저장소의 실험 데이터는 포함하지 않았다.

사진을 공개하지 않으므로 이 입력에 대한 수치를 외부에서 독립적으로 완전 재현할 공개 데이터셋은 제공하지 않는다. 공개 코드의 합성 도형·단위 테스트로 구조적 동작을 확인할 수는 있지만, 그것이 이 실사진 측정의 재현이나 전체 품질 검증을 대신하지 않는다.

## 사진 변환 범위

Depth Anything V2 small q8을 브라우저에서 실행해 상대 깊이를 얻고, 가정한 카메라로 보이는 면의 삼각형 메쉬를 만들었다. 정점 49,152개와 유지된 삼각형 96,277개를 기록했다. 깊이 경계에서 1,133개 삼각형은 연결하지 않았다.

이것은 2.5D 가시면 기준선이다. 뒷면·가려진 배경은 생성하지 않았으며, 절대 거리·카메라 보정·물체 형상을 실측한 결과가 아니다. GPU 장면 생성 모델은 실행하지 않았다.

## 픽셀 차이는 어떻게 읽어야 하나

- 기준 시점의 같은 영역을 192×256 sRGB로 비교했다. 채널값 범위는 0~255이다.
- MAE는 `mean(abs(render - reference))`, RMSE는 `sqrt(mean((render - reference)^2))`이다. RGB 채널과 평가 픽셀을 대상으로 집계한다.
- 낮은 값은 해당 원본 픽셀에 가깝다는 뜻이다. 지각 품질, 얼굴 식별, 의미 보존, 3D 형상 정확도 또는 보편적 알고리즘 우수성 점수가 아니다.
- 8,000점의 두 배치 방식은 같은 입력·메쉬·시드·참조 시점과 같은 화면 점 크기로 기록했다. 이 단일 관측에서 원본 시점 투영 가중의 픽셀 차이가 더 작았다. 여러 입력·시드에 대한 통계적 결론은 없다.
- 4,000/8,000/16,000점 비교에서는 화면 점 크기가 약 9.926/7.019/4.963 CSS px로 함께 변했다. 따라서 점 수만을 독립적으로 바꾼 실험으로 설명하지 않는다.
- 연속 메쉬 표면과 점묘는 표현 자체가 다르다. 메쉬의 픽셀 차이를 점묘의 직접적인 품질 순위로 사용하지 않는다.

## 구조 검사의 의미

+30°·−30°·180° 회전에서 점 버퍼가 그대로 유지됐고, 저장 파일을 다시 연 뒤에도 같은 점 지문을 확인했다. 지문은 회귀 점검용이며 실제 형상·숨은 면·시각 품질의 정답 증명이 아니다. 특히 180° 프레임은 앞면 점을 뒤에서 본 것으로, 복원된 뒷면이 아니다.

기록된 최대 산술적 재투영 차이 약 0.000169px는 같은 카메라 가정으로 만든 좌표 구성의 일관성을 검사한다. 추정 깊이가 정확하다거나 물체가 실제 3D 형상과 일치한다는 의미는 아니다.

해당 로컬 변환 버튼 검사에서 사진 업로드 요청은 0건으로 관측됐다. 최초 라이브러리·모델 다운로드는 필요하며, 이 한 번의 관측을 모든 환경에 대한 네트워크 감사 인증으로 표현하지 않는다.

## 아직 검증하지 않은 것

다수 사진·다수 시드의 일반화, 피사체·배경 분리 품질, 적은 점에서의 지각 품질, 실측 3D 정확도, 전체 GPU 모델 연동과 모바일 실기기 성능은 별도 검증이 필요하다. 향후 실험은 입력과 조건, 실패 사례와 한계를 함께 기록한다.
