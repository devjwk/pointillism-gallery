# 360° 자유 회전

메인 갤러리는 기본적으로 상하좌우 360° 자유 회전한다. 마우스 드래그·한 손가락 드래그·방향키에 같은 각도 처리를 적용한다. 각도가 ±π 경계를 넘으면 같은 방향을 유지하도록 정규화하며, 관성에도 이전의 하드 상한을 적용하지 않는다.

- **기본값:** `회전: 360° 자유`.
- **범위 제한:** 버튼을 누르면 `회전: 제한`으로 바뀐다. 기존 감상용 좌우 약 ±54°·상하 약 ±34° 범위를 유지한다. 드래그·관성에는 기존의 작은 완충 여유가 있다.
- **다시 자유 회전:** 같은 버튼을 다시 누른다. 모드 전환 시 남은 관성은 지우고, 제한 모드에서는 범위 안으로 각도를 정리한다.
- **초기화:** 기존 시점 초기화 버튼·더블클릭·두 번 탭·`0`을 사용한다.

이 수정은 카메라 조작 변경이다. 실제 메쉬·점을 뒤에서 볼 수 있게 하는 것이며, 물체 뒷면이나 가려진 배경을 새로 생성하지 않는다. 현재 가시면 기준선의 한계는 그대로다. 별도 검증 도구는 OrbitControls의 자유 회전을 이미 사용하며 이번 수정 대상이 아니다.

## 검사

기존 JS 29개에 회전 회귀 검사 6개를 추가해 총 **35개가 통과**했다.

1. 큰 누적 각도와 여러 바퀴를 정규화해도 삼각함수 기반 방향이 유지됨.
2. 마우스·터치 포인터 처리에서 두 축의 기존 상한과 한 바퀴 경계를 통과함.
3. 방향키 처리에서 두 축 모두 360°를 넘어 계속 회전함.
4. 자유 관성이 ±π 경계를 부드럽게 통과함.
5. 선택형 제한 모드의 범위·토글·관성 초기화가 유지됨.
6. 초기 상태와 버튼이 모두 자유 회전을 가리킴.

로컬 Chrome 브라우저에서는 실제 캔버스 드래그로 수평 약 176°·수직 약 165°의 후면 방향까지 확인했다. 수평 약 138°에서 오른쪽 방향키를 누른 뒤 약 143°로 이동해 이전 상한으로 되돌아가지 않는 것도 확인했다. 점 수 61,650개와 오류 없음 상태를 유지했다. 이는 해당 조작 확인 기록이며 성능 벤치마크나 뒷면 정확도 검증이 아니다. 실제 모바일 기기의 터치 동작은 이번에 별도 실행하지 않았다.

```sh
npm run build
npm test
```

수정 위치: `src/gallery/interaction/camera.js`, `src/gallery/render/frame.js`, 기본 상태·버튼 연결 및 생성된 `dist/gallery.js`. 이전 문서화 시점의 결과 JSON·시각 자료는 역사적 스냅샷으로 유지한다.
